# 类型模板库

> 读取时机：Phase 0 Step 0.2（业务填空）。根据 Q1 选择加载对应模板。
> 本文档为每种类型提供：默认值、触发词模板、输出格式模板、通用约束。

---

## A 类：查数据/排查问题（query_diagnose）

### 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 推荐模式 | P1（系统直查）或 P3（多步排查） | 单系统查询用P1，跨系统串联用P3 |
| 安全级别 | 只读（L1） | 查询类默认只读，不涉及数据修改 |
| 确认机制 | 不需要 | 只读操作默认无需确认 |
| 脱敏 | 按需 | 涉及手机号/地址时自动脱敏 |

### 触发词模板

```
查{对象}、{对象}查询、排查{对象}、{对象}怎么了、
{对象}异常、{对象}报错、看看{对象}、
trace {object}、check {object}、diagnose {object}
```

占位替换：`{对象}` → 用户在 A2 中填的关键字段对应的业务名词。

### 输出格式模板

**表格型（适合结构化数据）：**
```markdown
## 查询结果

| {字段1} | {字段2} | {字段3} | {字段4} |
|---------|---------|---------|---------|
| {值}    | {值}    | {值}    | {值}    |

共 {N} 条记录，查询时间：{time}
```

**时间线型（适合排查问题）：**
```markdown
## {对象} 状态追踪

时间线：
1. {时间1} — {事件1}（{状态}）
2. {时间2} — {事件2}（{状态}）
3. {时间3} — {事件3}（{状态}）

结论：{一句话结论}
建议：{下一步建议}
```

### 通用约束

- 查询超时：单次查询超过 30s 需提示用户缩小范围
- 结果上限：单次展示不超过 50 条，超过时提示分页
- 敏感字段：按 [quality-gates.md](quality-gates.md)「数据安全基线」统一脱敏规则执行
- 无结果：必须给出"可能原因"和"建议操作"

### 标杆示例

典型形态：把日志平台查询封装成自然语言入口的只读诊断 skill（按单号/时间范围检索，时间线整理输出）。

## B 类：生成内容/代码（generate）

### 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 推荐模式 | P5（护栏：生成+校验）或 P1（简单生成） | 有格式要求用P5，纯生成用P1 |
| 安全级别 | 生成只读（L1） | 生成代码不执行 |
| 确认机制 | 展示后确认 | 生成结果展示给用户确认 |
| 校验 | 建议开启 | 校验生成物的格式/语法 |

### 触发词模板

```
生成{产物}、创建{产物}、写一个{产物}、帮我{动作}{产物}、
{产物}模板、{产物}生成器、
generate {product}、create {product}、make {product}
```

占位替换：`{产物}` → 用户在 B1 中填的输出格式名词，`{动作}` → 写/建/生成/创建。

### 输出格式模板

**代码型：**
````markdown
## 生成结果

```{language}
{生成的代码}
```

### 校验结果
- [x] 语法正确
- [x] 包含必要字段：{fields}
- [x] 无禁止内容

### 使用说明
{如何使用这段代码}
````

**文档型：**
```markdown
## {文档标题}

{生成的文档内容}

---
生成时间：{time}
依据规范：{spec_source}
```

### 通用约束

- 禁止生成破坏性语句（DROP/DELETE/TRUNCATE）除非用户明确要求并确认
- 生成的代码必须包含注释说明
- 生成后自动做格式/语法校验（如 SQL 语法检查）
- 如有模板/规范，必须严格遵循

### 标杆示例

典型形态：按团队规范生成建表 SQL 的「生成+校验」skill；或按模板生成发布文档的文档型 skill。

## C 类：自动化操作（automate）

### 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 推荐模式 | P3（流程编排）+ P4（状态机辅助） | 多步操作用P3，有回退需求加P4 |
| 安全级别 | 写操作（L2/L3） | 默认需要确认 |
| 确认机制 | 关键步骤确认 | 写入/修改/删除操作前必须确认 |
| 回滚 | 必须支持 | 操作失败时有明确回退路径 |

### 触发词模板

```
{动作}{目标}、自动{动作}、批量{动作}、
帮我{动作}一下{目标}、把{对象}{动作}到{目标}、
auto {action}、batch {action}
```

### 输出格式模板

**操作报告型：**
```markdown
## 操作执行报告

### 执行摘要
- 操作类型：{type}
- 目标：{target}
- 状态：{成功/失败/部分完成}
- 耗时：{duration}

### 执行详情
| 步骤 | 操作 | 状态 | 备注 |
|------|------|------|------|
| 1 | {op1} | ✓ | |
| 2 | {op2} | ✓ | |
| 3 | {op3} | ✗ | {失败原因} |

### 后续建议
{如有失败步骤的处理建议}
```

### 通用约束

- 所有写操作执行前必须展示操作计划并等待确认
- 必须有失败回退方案（回滚/重试/人工介入三选一）
- 批量操作需先用小批量试跑（如前 3 条）
- 操作日志必须完整记录（成功和失败都记）
- 涉及金额/权限变更的操作，安全级别提升为 L3（双重确认）

### 安全操作级别

| 级别 | 定义 | 确认方式 |
|------|------|---------|
| L1 | 只读操作 | 无需确认 |
| L2 | 写入/修改（可回滚） | 单次确认 |
| L3 | 删除/不可逆操作 | 双重确认 + 展示影响范围 |

### 标杆示例

典型形态：带操作确认与失败回退的多步骤写入自动化 skill（如跨系统下发测试数据、设备远程操作）。

## D 类：数据处理/对账（data_process）

### 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 推荐模式 | P3（流程：读取→处理→输出）+ P5（护栏：校验） | 标准数据处理管道 |
| 安全级别 | 只读+文件写入（L1-L2） | 读源数据只读，写结果为新文件 |
| 确认机制 | 处理前确认范围 | 展示将要处理的数据量和规则 |
| 数据保护 | 不覆盖原文件 | 结果总是写入新文件 |

### 触发词模板

```
对账、数据对比、数据核对、汇总{对象}、{对象}报表、
{时间}报告、数据清洗、格式转换、
reconcile、compare data、summary report、monthly report
```

### 输出格式模板

**对账报告型：**
```markdown
## 对账结果

### 概要
- 数据源A：{source_a}（{count_a} 条）
- 数据源B：{source_b}（{count_b} 条）
- 匹配：{match_count} 条
- 差异：{diff_count} 条

### 差异明细
| 序号 | {key_field} | 源A值 | 源B值 | 差异说明 |
|------|------------|-------|-------|---------|
| 1 | {id} | {val_a} | {val_b} | {desc} |

### 结论
{一句话结论}
```

**汇总报表型：**
```markdown
## {时间段} {对象} 汇总报表

### 总览
- 总量：{total}
- 环比：{mom}%
- 同比：{yoy}%

### 明细
| {维度} | {指标1} | {指标2} | 占比 |
|--------|---------|---------|------|
| {dim1} | {val1}  | {val2}  | {pct}% |

生成时间：{time}
数据范围：{date_range}
```

### 通用约束

- 原始数据只读，结果写入新文件（绝不覆盖源文件）
- 大数据量（>1000行）处理前展示"处理计划"并确认
- 数值计算结果保留 2 位小数
- 涉及金额的字段单位明确标注（元/分）
- 异常数据（空值/格式错误）标记后跳过，不中断整体流程

### 标杆示例

典型形态：月度业务汇总报表生成 skill；或两数据源充值的差异对账 skill。

## E 类：流程串联（orchestrate）

### 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 推荐模式 | P3（流程编排） | 多步骤有序执行 |
| 安全级别 | 视各步骤而定 | 每步独立评估安全级别 |
| 确认机制 | 关键节点确认 | 至少在第一步和最后一步前确认 |
| 容错 | 步骤级 | 某步失败不影响已完成步骤 |

### 触发词模板

```
帮我{完整流程描述}、执行{流程名}、跑一下{流程名}、
{流程名}流程、从{起点}到{终点}、一键{流程名}、
run {process}、execute {workflow}
```

### 输出格式模板

**流程执行报告型：**
```markdown
## 流程执行报告：{流程名}

### 执行状态：{成功/部分完成/失败}

| 步骤 | 名称 | 状态 | 耗时 | 产出 |
|------|------|------|------|------|
| 1 | {step1} | ✓ | {t1} | {output1} |
| 2 | {step2} | ✓ | {t2} | {output2} |
| 3 | {step3} | ✗ | {t3} | {error} |

### 最终产出
{最终结果或中间结果}

### 后续操作
{如有失败步骤的建议}
```

### 通用约束

- 每步必须有明确的"完成标志"（如何判断这步做完了）
- 步骤间数据传递必须显式（不依赖隐式状态）
- 支持从中间步骤恢复执行（断点续跑）
- 总执行时间超过 5 分钟需展示进度
- 并行步骤标注清楚，串行步骤说明依赖关系

### 标杆示例

典型形态：串起「查询 → 整理 → 报告」全链路的端到端流程 skill（每步有完成标志，支持断点续跑）。

## 通用默认值（兜底）

当用户跳过某个填空题时，使用以下默认值：

| 跳过项 | 默认值 | 标注 |
|--------|--------|------|
| 名字（F1） | 从 F2 自动提取关键词 | `[auto-named]` |
| 异常处理 | "提示错误信息并停止" | `[default]` |
| 确认机制 | "关键操作前确认" | `[default]` |
| 数据脱敏 | "涉及手机号/地址时脱敏" | `[default]` |
| 输出格式 | "Markdown 格式化输出" | `[default]` |
| 查询超时 | "30s 超时提示" | `[default]` |
| 结果上限 | "单次最多 50 条" | `[default]` |

所有使用默认值的字段，在最终 SKILL.md 中用注释标注 `<!-- [default] 建议验证 -->`，提醒后续优化时关注。
